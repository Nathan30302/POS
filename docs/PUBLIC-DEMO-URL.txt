NEXORA public demo URL
======================

## Durable hosting: Railway (preferred)

Main includes the Railway boot fix (3d78e7a): missing JWT / MoMo secrets and
CORS / shop origins no longer crash the process before listen. Secrets are
auto-provisioned and persisted under /data when a volume is mounted; CORS and
SHOP_PUBLIC_ORIGIN derive from RAILWAY_PUBLIC_DOMAIN when unset.

In-repo: Dockerfile, railway.json, railway.toml, scripts/docker-entrypoint.sh

### Redeploy (service already linked)

  From /Users/mac/POS (with Railway CLI logged in):
    railway up

  Or: push to the connected GitHub branch / Redeploy in the Railway dashboard.

  Do not override the start command — image CMD runs docker-entrypoint.sh
  (migrate + optional seed, then node).

### First-time / checklist

  1. railway login   (or deploy via Railway GitHub integration)
  2. Create service from this repo (Dockerfile builder; see railway.toml)
  3. Attach a Volume mounted at /data  (SQLite + uploads + auto-secrets)
  4. Generate a public HTTPS domain in Railway settings
  5. Redeploy; wait for /api/health → 200
  6. Optional: set SEED_ON_BOOT=1 once for demo users (default in image is 1)

  Explicit secrets are optional for demo boot (auto-provisioned). For a stable
  production shop, set JWT_SECRET, MOMO_WEBHOOK_SECRET, CORS_ORIGIN, and
  SHOP_PUBLIC_ORIGIN yourself.

### After deploy

  Share the Railway HTTPS URL from the service settings.
  PDF:  <your-railway-url>/docs/NEXORA-for-business.pdf
  Health: <your-railway-url>/api/health

## Local / temporary only (laptop must stay on)

  Tunnels (trycloudflare, etc.) and LAN IPs are not laptop-off durable.
  Prefer Railway above. Same-Wi‑Fi only: http://127.0.0.1:4000

  fly.toml + Dockerfile still work. Prefer Railway for this demo unless you
  already run Fly. Volume + secrets story is the same idea: persist /data.
